# AI Playlet Agent

这是一个短剧创作指挥台的前端演示页面，重点展示“灵感输入、推演展示、创作控制、格式输出”这一套交互流程。

## 功能介绍

### 1. 灵感输入区

页面左侧提供一组短剧创作输入能力，用来快速搭出一个故事起点，包括：

- 题材选择
- 创作模式选择
- 主角设定
- 反派设定
- 情节主线
- 自定义标签输入

页面还提供“随机生成灵感”按钮，可以快速替换题材、主角和反派，形成新的创作组合。

### 2. 群聊式推演展示区

页面中部使用聊天流的方式模拟角色互动，让短剧推演不再以大段文本展示，而是更接近“现场演绎”的感觉。

展示内容包括：

- 动作描写
- 人物对白
- 内心独白

点击“开始一轮推演”后，页面会以逐字输出的方式播放示例内容，模拟剧情推进过程。

### 3. 剧本结构树

聊天区旁边保留了一棵结构树，用来概览一集内容的推进节点，例如：

- 钩子开场
- 第一次对峙
- 节奏推进
- 反转收束

它的作用不是替代正文，而是帮助使用者快速理解“这一场戏当前推进到哪里了”。

### 4. 导演与监制控制区

页面右侧提供一组创作控制组件，用来模拟创作中的节奏干预：

- 最大演绎轮数滑杆
- 回档控制滑杆
- 咔 Cut 按钮
- Continue 按钮
- 导演指令输入框
- 监制建议区

这部分强调的是“创作过程可打断、可调整、可重写”，而不是一次性吐出结果。

### 5. 格式输出区

页面底部提供一个格式化输出区域，会把当前输入整理成更接近剧本样式的文本片段，方便查看成品感。

同时页面还放了一个请求示例展示区域，用来说明页面内部的数据结构长什么样，但它在当前版本里只是静态演示内容。

## 设计思路

### 一、把创作流程拆成四个视觉阶段

整个页面不是按传统表单来排，而是按创作过程拆成四块：

- 灵感输入
- 推演展示
- 过程控制
- 结果输出

这种布局更贴近真实使用场景，因为用户通常不是先填完所有字段再看结果，而是一边改设定，一边观察演绎，一边干预节奏。

### 二、用“聊天流”替代普通文本块

短剧内容本质上是人物冲突和情绪碰撞。如果直接用大段文字堆在页面上，可读性会很差。

所以这里用聊天流承载：

- 谁在说话
- 说了什么
- 当前动作是什么
- 当前情绪是否变化

这样做的好处是页面更容易产生“正在发生”的感觉，适合展示短剧这种高冲突、高节奏内容。

### 三、让控制区与展示区并列

控制组件没有被放在设置面板底部，而是单独成为一个区域，原因是它在这个页面里不是附属功能，而是核心操作。

页面想表达的不是“填写信息然后生成”，而是“边看边调、边演边改”。

所以控制区需要和聊天区并列，形成明显的操作关系。

### 四、保留结构树与成品预览两个视角

这个页面同时提供两种阅读方式：

- 结构树：看场景推进结构
- 剧本预览：看最终文本效果

前者偏过程，后者偏结果。两者同时存在，可以避免页面只剩“热闹交互”而缺少成品落点。

### 五、视觉上强调“指挥台”而不是“表单页”

从命名和布局上，这个页面都更像一个创作台，而不是简单的输入页。

设计重点包括：

- 用卡片分区明确不同阶段
- 用状态文字显示当前演示进度
- 用按钮、滑杆、提示卡强化控制感
- 用预览区强化输出感

整体思路是让页面看起来像一个可操作的创作工作台。

## 三个文件分别做什么

### [index.html](index.html)

负责页面结构，也就是所有模块在页面上的布局和层次。

它定义了：

- 顶部主视觉区域
- 灵感输入面板
- 推演展示面板
- 导演控制面板
- 格式输出面板
- 聊天消息模板

可以把它理解成整个页面的骨架。

### [styles.css](styles.css)

负责页面的视觉表现，包括：

- 配色
- 字体
- 卡片样式
- 网格布局
- 按钮状态
- 聊天气泡表现
- 响应式呈现

它决定了这个页面看起来像不像一个“短剧创作指挥台”。

### [app.js](app.js)

负责页面上的交互逻辑和演示数据。

它主要处理：

- 默认数据初始化
- 标签渲染
- 结构树渲染
- 监制观察列表渲染
- 聊天消息输出
- 逐字流式演示效果
- 随机灵感生成
- 指令注入
- 剧本文本格式化预览

也就是说，页面上的动态变化基本都由它驱动。

## 页面使用方式

这是一个静态前端页面，直接打开 [index.html](index.html) 就可以查看效果。

建议的体验顺序是：

1. 先点击“随机生成灵感”观察输入区变化
2. 再点击“开始一轮推演”查看聊天流播放效果
3. 使用右侧控制区尝试插入指令或切换状态
4. 最后点击“生成标准剧本”查看文本预览区

## 当前页面特点

- 结构清晰，按创作阶段组织内容
- 交互密度高，适合展示产品概念
- 既能看过程，也能看输出结果
- 页面元素之间关系明确，不是单纯堆表单

## 当前页面局限

- 页面中的内容目前是演示数据
- 推演结果是预设脚本，不会自行扩展剧情
- 请求示例区域仅用于展示数据结构样式
