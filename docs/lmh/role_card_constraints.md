# 角色卡约束

最新修改：2026-04-17 21:10

说明：面向团队内部评审的约束文档，用于快速确认角色卡、群聊 UI 和聊天记录窗口在本轮原型中的边界、范围和不做项。

## 当前目标

本轮“角色卡”指的是：

- 角色详情查看入口
- 角色基础信息展示
- 角色历史发言记录查看
- 基础检索与筛选能力

不是重新讨论“如何生成角色”。

## 约束 1：交互定位

角色卡的交互直觉可以参考 QQ / 微信聊天界面，但不能直接照搬。

本轮应强调：

- 通过群聊消息中的角色头像进入详情
- 在详情面板中查看基础信息和历史记录
- 历史记录以“聊天可追溯”的直觉组织

当前进一步收敛为：

- 暂不采用右侧抽屉
- 暂不提供“当前对话角色列表”统一入口
- 暂时只保留从群聊 UI 中点击对应角色头像进入角色卡这一种主入口

## 约束 2：信息范围

角色卡至少覆盖：

- 姓名
- 性别
- 年龄
- 身份
- 外观标签
- 性格标签

历史记录至少覆盖：

- 第几集
- 场景或轮次
- 说了什么
- 时间顺序

## 约束 3：筛选能力

本轮方案必须考虑：

- 按集数筛选
- 按关键词搜索
- 按时间顺序查看

“只看与某一对象的互动片段”可以作为扩展项保留，但不应反客为主。

## 约束 4：实现边界

本轮默认不要求：

- 真实接后端
- 完整实现搜索服务
- 把角色卡扩成完整人物档案系统

如果后续做静态原型：

- 可以使用 mock 数据
- 可以在前端本地完成筛选和搜索演示

## 约束 5：阶段 3 对话区方向

用户已明确阶段 3 的主视觉方向应进一步靠近 QQ / 微信聊天界面的使用直觉。

当前应固定以下约束：

- 阶段 3 的群聊式推演沙盒占据页面中部主要区域
- 剧情推进时，角色输出应表现为“收到一条聊天消息”
- 每条角色消息至少展示：
  - 头像
  - 角色名
  - 消息内容
- 当前顶部“短剧创作指挥台”应压缩
- `运行模式 / Session / 当前状态` 优先压缩到同一行展示

注意：

- 这里参考的是聊天产品的交互直觉，不要求视觉上直接复刻 QQ 或微信
- 群聊消息流需要继续兼容剧情事件、导演控制和系统提示等非角色消息

## 约束 6：角色卡历史展示范围

当前已明确：

- 角色卡主视图中的历史记录，仅展示当前集前几轮的角色内容
- 排序采用“最新在上”
- 首版同时展示：
  - `thought`
  - `action`
  - `dialogue`

另外需要提供一个“聊天记录”按钮：

- 点击后进入该角色更完整的历史聊天浏览视图
- 该视图用于查看此前历史会话中的全部聊天记录

## 约束 7：角色卡承载形态

当前已明确采用分层方案：

- 点击群聊消息中的角色头像，先打开居中的角色卡弹窗
- 角色卡首屏仅承载：
  - 角色基础信息
  - 当前集前几轮记录
- 点击“聊天记录”后，再打开一个更大的二级窗口
- 二级窗口用于承载跨历史会话的完整聊天记录、搜索与筛选

当前不采用：

- 右侧抽屉
- 在同一个小弹窗里硬塞完整历史记录

## 约束 8：聊天消息卡片

当前已明确：

- 单条角色消息中，`thought / action / dialogue` 需要分段展示
- 角色名显示在头像右侧上方，消息气泡位于其下
- 点击消息气泡本身暂不触发额外交互
- 系统 / 导演 / 监制消息需要保留时间或 turn 标记，便于追溯

## 约束 9：顶部状态栏与角色卡信息范围

当前已明确：

- 顶部“短剧创作指挥台”压缩后，仅保留：
  - `运行模式`
  - `Session`
  - `当前状态`
- 顶部状态栏采用固定悬浮
- 角色卡顶部暂不增加“与当前剧情关系”这类动态摘要区
- 角色卡标签采用：
  - 静态标签
  - 动态标签

其中动态标签可包括但不限于：

- 当前情绪
- 当前立场
- 当前冲突对象

## 约束 10：完整聊天记录组织方式

当前已明确：

- “聊天记录”二级窗口默认按集分组
- 每一集内部再按时间流展示

## 约束 11：完整聊天记录检索规则

当前已明确：

- 关键词搜索默认覆盖：
  - `thought`
  - `action`
  - `dialogue`
- 搜索命中后，结果仍保留“按集分组”的组织方式
- 需要提供类型筛选：
  - `全部`
  - `thought`
  - `action`
  - `dialogue`
- 分组展开策略采用：
  - 默认展开当前集
  - 其余集默认折叠
- 单条历史记录固定展示的元信息优先包含：
  - `集数`
  - `scene`
  - `turn`
  - `kind`

## 约束 12：阶段 1 角色卡列表展示

当前已明确：

- 阶段 1 主页面角色区应展示全部角色卡，不再限定为“核心角色卡”。
- 当角色卡数量超过 3 张时，默认只显示 3 张。
- 必须提供展开/收起交互：
  - 默认文案可为“查看更多（共 N 个角色）”
  - 展开后可收起回 3 张视图
- 非核心定位角色（如配角）也必须可见，不应被过滤隐藏。
