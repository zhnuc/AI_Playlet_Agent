# 以 `test/lmh-context-v1` 为主干融合 `dev-wzw` 的短剧创作 Agent 方案

## Summary
- 结论是不建议直接做 `git merge`。`test/lmh-context-v1` 应作为运行时主干，因为它已经具备事件真源、角色私有记忆、单集/整季主循环、日志/checkpoint、跨集摘要与回归测试思路；`dev-wzw` 更适合作为产品能力来源来回迁。
- `dev-wzw` 的价值主要在产品交互层：用户审稿改纲、多人点名、多轮回档、临时导演指令、群聊式演绎感。
- `test/lmh-context-v1` 的价值主要在工程底座：`RuntimeState`、`RoleMemory`、`SeasonContext`、`context_builder`、`event_committer`、`scheduler`、`run_episode/run_season`。
- 本地无法实际执行测试，因为当前环境没有可用的 `python` / `uv`；下面方案基于静态阅读、分支 diff、现有测试代码与产品文档整理。

## Key Changes
- 新整合分支从 `test/lmh-context-v1` 拉出，禁止把 `dev-wzw/run.py` 原样并回来；只迁移其需求与交互语义，按现有模块化结构重写。
- 统一系统分成 6 层：`input adapter`、`planner/review`、`scene runtime`、`director/monitor`、`formatter/exporter`、`season memory/checkpoint`。
- 保留当前 `planner_output` schema，继续要求 `scene_roles`、`first_speaker`、`character_directives`，这样能直接服务现有 runtime。
- 新增 `RunMode = planned | free`。`planned` 走完整大纲；`free` 不直接让角色裸聊，而是先生成一个最小 `episode_plan`，再进入同一套 runtime，避免两套引擎分叉。
- 角色输出接口统一到 `next_speakers: list[str]`。旧 `next_speaker` 只做兼容读取，进入 scheduler 前统一归一化。
- 当 `next_speakers` 长度为 1 时沿用现有单链路；长度大于 1 时实现“队列化回应”，不做真并发。
- 在 `RuntimeState` 中增加 `InteractionState { mode, initiator, pending_queue, trigger_event_id }`，采用“一人发起、多人顺序回应、发起者收束”的固定结构。
- 保留事件驱动架构，但不继承 `dev-wzw` 中让模型直接输出 `visible` 的设计；`visible_to` 改为由引擎按规则决定，默认 `thought` 仅自己可见，`action/dialogue` 对 `scene_roles` 可见。
- `dev-wzw` 的“用户改纲”改造成显式 `planner_review` 流程：用户反馈进入 planner prompt，高优先级重新生成大纲，审核通过后再冻结为 episode baseline。
- `dev-wzw` 的“回档 + 临时反馈”改造成显式 `director_command`：支持 `rollback(step)`、`inject_instruction(role|scene)`、`pause`、`resume`、`cut`，其中 temporary feedback 只作用下一轮，不写入长期 memory。
- 保留当前 `director.py` 规则式截断作为硬兜底，再新增可选 `monitor_agent.py`，每 N turns 给出 `continue / cut / suggestion`；没有 monitor 时系统也能完整运行。
- 新增 `formatter_agent.py`，把 event log 转成两类产物：标准短剧台本与 shotlist JSON，为后续生图/生视频链路做接口。
- Provider 层继续保持 OpenAI-compatible 抽象；如果要接 Coze，只做 adapter，不把核心 runtime 绑死在 Coze Workflow/Bot 上。
- 先拆出 CLI/API 层。CLI 负责 demo；HTTP/SSE API 暴露 planner review、episode run、season run、director command、export，给后续前端导演控制台复用。

## Public Interfaces / Types
- `planner_output.episodes[*]` 保持 `episode_number / global_plot / place / scene_roles / core_conflict / plot_twist_or_hook / first_speaker / character_directives`。
- `role_turn_output` 统一为 `Inner_Thought / Action / Dialogue / next_speakers`，内部不再以单值 `next_speaker` 为主。
- `Event.kind` 至少包含 `thought / action / dialogue / system / director / monitor`。
- `DirectorCommand` 固定为 `approve_outline / revise_outline / rollback / inject_instruction / pause / resume / cut`。
- `ExportArtifact` 固定为 `script / shotlist / season_summary`。

## Test Plan
- 单元测试覆盖 `next_speaker` 归一化、多人队列 open/pop/close、initiator 收束、非法路由重试、director rollback 后 state/memory/checkpoint 一致性。
- 集成测试覆盖 `planned` 模式两集 continuity、`free` 模式单集起跑、planner review 后 schema 稳定、monitor suggestion 注入后下一轮 prompt 生效、formatter 输出固定 schema。
- 回归测试保留现有 private summary、season checkpoint、fallback prompt 用例，并补 `director_command` 与 `queue controller` 用例。
- 演示验收固定为 5 步：输入 logline 和角色卡；生成并审核分集大纲；进入群聊式演绎；支持多人点名/回档/临时指令/监制 cut；集末导出台本与分镜 JSON。

## Reference Patterns
- `StoryWriter` 适合借鉴“outline + planning + writing + dynamic compression”的三段式叙事架构，和你们“总策划 + 单集计划 + 角色演绎”最贴近。https://arxiv.org/abs/2506.16445
- `AutoGen Group Chat` 明确采用“manager 选下一位发言者，顺序执行而非真并发”的群聊模式，非常适合你们的群聊沙盒和 queue controller。https://microsoft.github.io/autogen/dev/user-guide/core-user-guide/design-patterns/group-chat.html
- `CAMEL` 适合借鉴“角色扮演 + critic in the loop”，可映射为角色 Agent 与监制 Agent。https://arxiv.org/abs/2303.17760
- `MetaGPT` 适合借鉴 SOP/装配线式协作，避免多 Agent 漫聊和级联幻觉。https://arxiv.org/abs/2308.00352
- `MM-StoryAgent` 适合借鉴从文本到图像/语音/视频资产的多阶段、多模态生产链，适合你们后续从“剧本”走向“成片”。https://github.com/X-PLUG/MM_StoryAgent
- `SkyScript-100M` 是短剧领域直接相关的数据资产，可用于 shotlist schema、few-shot 示例和后续评测。https://arxiv.org/abs/2408.09333

## Assumptions
- 先做后端引擎与 CLI/API demo，不先做完整前端导演台。
- “完整短剧创作 Agent” 的当前定义是：输入角色与故事核、生成可审阅大纲、可导演式推演、可跨集承接、可导出台本/分镜。
- 公开可直接复用的“AI 短剧多智能体互动”资料其实不多；更有价值的参考主要来自叙事 multi-agent、群聊编排、短剧数据集和多模态生产链这四类。
