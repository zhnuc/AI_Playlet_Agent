# Git 版本管理约定

## 目标
用最小成本保证个人开发可回退、可验证、可同步，避免实验代码直接污染稳定分支。

## 分支职责
- `main`：远端默认分支或团队公共稳定分支，不直接做实验。
- `lmh`：个人稳定分支，只保留已经验证通过、可继续开发的内容。
- `test/*`：个人实验分支，每个分支只验证一个功能点或一个方案假设。

## 日常流程
1. 在 `lmh` 上保持可运行状态。
2. 开始新实验时，从 `lmh` 创建 `test/*` 分支。
3. 在 `test/*` 分支中只做一个目标，不混入无关改动。
4. 本地验证通过后，再合并回 `lmh`。
5. 对外同步时，优先推送 `lmh`，不默认推送未验证的实验分支。

## 分支命名
- 推荐：`test/langgraph-baseline`
- 推荐：`test/context-memory`
- 推荐：`test/director-writer-flow`
- 不推荐：`test1`、`tmp`、`new-branch`

## 提交原则
- 一次提交只解决一个问题。
- 先验证，再提交。
- 不把“顺手修改”和“核心改动”混在同一次提交里。
- 提交前检查改动范围，避免把无关文件一起提交。

## 提交信息
- 保持简短、明确、可回看。
- 推荐格式：`type: 简要说明`

示例：
- `feat: 增加导演到编剧的主流程`
- `fix: 修复角色历史记录回档逻辑`
- `docs: 补充上下文管理设计说明`
- `chore: 初始化 uv 和 Python 3.11 环境`

## 合并原则
- `test/*` 合并回 `lmh` 前，必须确认该实验目标已经单独验证通过。
- 如果实验失败，不强行合并，直接保留记录或删除实验分支。
- `lmh` 合并到团队公共分支前，应再次检查是否存在仅个人使用的实验性代码或本地配置。

## 当前项目默认做法
- 当前阶段以 MVP 和主流程跑通为主。
- 优先小步提交，不做大而全的长分支开发。
- 涉及多智能体流程调整时，优先按功能点拆分到不同 `test/*` 分支验证。
- 如果 Git 操作与本约定冲突，应先说明原因，再执行偏离方案。

## Worktree 使用补充
- 当前本地目录约定为：`AI_Playlet_Agent -> test/lmh-context-v1`、`AI_Playlet_Agent-input -> lmh-input`、`AI_Playlet_Agent-summary -> lmh-summary`、`AI_Playlet_Agent-integration -> integration 本地联调分支`；进入哪个目录，就只在该目录对应的分支上工作。
- 每次打开 Codex 或开始修改前，先执行 `git branch --show-current` 和 `git status --short`，确认“当前目录”和“当前分支”一致，且没有误带入不属于本任务的未提交改动。
- `AGENTS.md`、`tasks/`、`.env`、`.venv` 属于本地共享协作资料，多个 worktree 可能通过软链接共用；修改它们前先确认是否希望同步影响其他目录，默认不要把这类本地共享文件混入功能分支提交。
